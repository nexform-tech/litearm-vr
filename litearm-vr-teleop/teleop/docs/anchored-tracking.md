# 固定锚点遥操与漂移修复

当前实现使用固定握持参考生成完整TCP位姿，控制循环持续跟踪该目标。目标不再由
“当前仿真末端＋本帧手柄增量”构造。死区、IK未收敛与执行限幅不会改写握持参考。

## 输入与坐标语义

握持时记录手柄位置/姿态与当前TCP位置/姿态。平移目标为
`p_tcp0 + translation_remap.T @ (p_hand - p_hand0)`。
所有后端采用固定世界平移轴；旧pybullet随手柄朝向改变平移轴的行为已移除。
`tool`旋转采用握持时手柄自身坐标系的相对旋转，映射到握持时TCP自身坐标系；
`base_link`采用世界系相对旋转。使用正交矩阵共轭，不累计欧拉角或旋转向量。
旋转符号必须是可组合的合法旋转映射（±1且乘积+1），非法标定启动时拒绝。

目标位置和姿态使用按时间换算的一阶低通；姿态滤波在SO(3)进行。
`deadband.t_in/t_out`现在单位是米，`r_in/r_out`是弧度，均不是每帧增量。
平移和旋转独立滞回，比较完整滤波目标与保持输出；小动作累积超过容差会更新。
`smooth_alpha`保留60Hz下的权重含义；`rest_confirm_frames`仅为旧配置兼容项。

控制的是配置中的TCP；交给法兰IK前仍计算
`p_flange = p_tcp - R_target @ tcp_offset`，纯旋转不会故意平移工具尖。

## 控制循环与保持

网络输入只更新目标，IK在`sim.freq`控制循环运行。没有新输入时在输入有效期内
仍追踪目标。临时速度/加速度限幅不删除未完成的位姿误差。
`tracking.max_joint_velocity/max_joint_acceleration`约束所有后端的执行指令；
笛卡尔中间参考另受线速度、角速度约束。原求解器步长界仍作为候选解兜底。

`tracking`段提供输入/反馈有效期、最大跟踪误差、无进展超时、跳变阈值和收敛容差。
输入超时、无效数值、源时钟异常、反馈失效、执行指令与实测TCP严重脱节时保持。
短暂追踪丢失先暂停，输入有效期内恢复则继续；超过有效期才锁定保持。
同一握持不会自动恢复：必须先观察到有效的grip松开，再握持重新锚定。
紧急保持/松开会清除追赶，普通跟踪的加速度约束不用于延迟故障停止。

位置容差与旋转容差允许有界残差；不承诺VR追踪系统自身漂移、标定误差或真机柔性误差为零。
不可达目标保留最新绝对目标并持续求解可行方向，不锁定握持；手柄回到可达范围后自动跟随。
没有可行运动方向时仍可能静止，软件不能让机械臂穿过关节限位或不可达区域。

## 真机握持流程

1. 客户端后台按每臂最多20Hz查询`state`，连接与查询不阻塞另一臂的控制。
2. 握持前必须有七轴新鲜实测关节角；没有反馈则拒绝启动。
3. 发送`start`，等待成功回执及启动后的新鲜实测状态，期间不发送关节目标。
4. 用此时实机TCP和最新手柄位姿建立锚点，开始跟踪。启动等待超过5秒则保持。
5. 松开/失效发送`hold`，丢弃旧目标并保持实测位置（反馈失效时保持最后下发位置）。

首次握持不再自动回home；双击grip回home也已移除，`double_click_s`兼容读取但不生效。
需要归位时显式使用跟随服务的已有home/movej流程，并在完成后重新握持。

客户端不会把关节命令回执当成测量。测量年龄包含服务端报告年龄和网络往返时间；
断线立即使缓存失效。STM32通过连续状态序号推进验证流仍活跃；SDK需提供
`feedback.joints[].fresh/age_s`。服务端和客户端必须一起更新。
SDK版还要求原有`joint_follow`接口及能在握持前提供实测反馈；支持
`connect(read_only=True)`的版本会先只读连接，旧版缺少该能力则明确拒绝闭环启动。
不能证明反馈新鲜度时不会静默退回开环。仓库外SDK版本兼容性需要部署时确认。

## 输入队列

bridge发布队列与teleop接收队列均保留每次按钮/追踪状态变化的首帧与最新位姿。
同状态中间位姿允许合并，存留帧内容不改写。按钮边沿积压到队列溢出时发送
`teleopInputFault`屏障，消费者进入保持并要求重新握持。发布失败恢复也先发送屏障。
`frames_dropped`现在包含合并的旧位姿，不再等同于网络丢包。
输入时间戳使用相对时差检查，无需两机绝对时钟同步；无法识别首次到达前的既有延迟，
没有源时间戳的旧客户端只能使用本地输入超时保护。

## 验证与运行

在teleop目录运行`make test`。默认测试使用PyBullet DIRECT，不连接真机或ROS。
覆盖固定目标100次往返、慢动作、跨180°、帧率与丢帧、独立死区、真实IK往返、
TCP原点旋转、三个IK后端、速度/加速度界、不可达恢复、松开、断流、双臂独立、
启动握手和反馈协议。Pink未安装时对应测试明确跳过。

跟随协议测试：在`litearm-vr-follow`运行`python -m unittest test_measured_state.py`。
桥接回归：在`litearm-vr-bridge`运行`PYTHONPATH=src python -m pytest tests`。

离线验证不能替代真机验收。部署后先确认反馈有效、方向映射和TCP标定，再用低速小幅
往返测量实机TCP误差；参数应基于静止噪声、执行器能力和所需重复精度调整。

## 手柄领先与执行异常的区别

手柄领先机械臂的位姿差不再触发锁定保持；控制器保留握持锚点，按既有速度/加速度
约束追踪最新绝对目标。`max_position_error/max_rotation_error`仅比较上一周期
已限速执行指令的TCP与实测TCP，检测真正的执行偏差。仿真没有实测反馈时不触发
此项硬件保护。断流和实机执行异常的保护仍生效。

## 快速手柄与特殊构型

超过 `hand_jump_position/hand_jump_rotation` 的孤立样本暂不更新目标；下一连续样本
确认后接受完整位移。单帧尖峰不污染目标，确认过程不改变握持锚点。持续不一致的
样本不能刷新有效输入时间，仍受 `input_timeout` 保护。

exact 后端优先使用精确解，速度盒内无法完整实现时使用带关节约束的阻尼最小二乘，
跟随可行方向。Pink QP失败使用同样的回退。所有候选仍经过统一速度/加速度限制。
`stall_timeout` 仅标记探针 `constrained`，不再锁定；松开 grip 仍立即取消追赶。
这些变化不会提高现有配置的速度上限，也不会取消真实执行偏差保护。
